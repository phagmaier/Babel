## Method

Phase 1: five finder agents covered the repository in parallel, one per angle (correctness, slop, simplification, spec challenge, tests). Phase 2: each finding was handed to a separate skeptic agent instructed to refute it by reading the code, rerunning searches, and where possible reproducing behaviour in scratch tests outside the repository. Phase 3: this file. A finding appears below only with its skeptic's verdict; where the skeptic corrected the finder, the corrected version is what is stated, and refuted parts are listed under "Dropped or refuted". Several skeptics checked by mutation: they ran the full vitest suite against in-memory mutants of a module to see whether removing a guard fails any test.

Limits that apply throughout: nobody launched the native app; claims about what a writer sees come from reading JSX/CSS and from tests run in JSDOM. No cargo build or cargo test was run. Line estimates for removals come from reading, not from trial refactors. Effort: S under an hour, M about half a day, L days, unless a section states its own scale (the DESIGN items use days/weeks and say so).

## What to act on first

1. **C-01 and C-02**: ordinary typing puts the draft in a state where nothing is journaled or saved, with an alert that does not say where the problem is. On a Fountain file written by another tool, pressing Enter after a scene heading and typing one character is enough (C-01); on any file, so is a space at the edge of bold text (C-02). Both are the same failure mode: a capture that throws stops all protection. Making capture failure non-fatal to journaling fixes the class.
2. **D-02**: after any edited session, every later open silently fails all checkpoints and saves until the writer finds a panel and clicks "Keep Current File". The skeptic judged the current design a loss path.
3. **D-01**: the single-Enter flow in the spec's own Enter table writes Fountain that Babel's PDF pipeline and other parsers misread. A 1–3 day fix exists (insert the separator row on Enter).
4. **C-04**: clicking or moving the caret rewrites the manuscript file with identical bytes and clobbers the retained previous generation.
5. **D-08 (A)**: no Reload on external change, which `SPEC.md` S10.7 requires and no task covers.
6. **D-03**: the editor renders every screenplay element as an identical left-aligned line, and nothing in the plan changes that before the owner pilot.
7. **D-07, T-01 and T-02**: no test types a multi-element scene from empty or edits around unforced Fountain syntax, which is how C-01 and D-01 passed three milestone exits; and CI has not run any `src-tauri` test since M4-12.
8. **C-03, C-05, C-06**: backslash escapes printed in the PDF; saves fail on SELinux hosts; Find highlights vanish on Next match.

### C-01 — On a standard Fountain file, typing under a heading or above a character cue makes the draft uncapturable; nothing is journaled or saved until that edit is reverted (high; M for the seven cases, L to close the whole class)

- Evidence: `src/domain/fountainCodec.ts:773-784` (`replaceLines` returns the prior source text for any row whose kind and text are unchanged, so an unforced `INT. HOUSE - DAY` is never re-emitted with a `.` marker when its neighbours change); `fountainCodec.ts:305-319, 254-257` (unforced headings and transitions need blank lines both sides; automatic cues need a preceding blank); `src/editor/sourceBridge.ts:338-364` (the same-row-count branch has no neighbour widening; the structural branch at `:306-336` widens only on `neighbor-drift`, then fails `round-trip`); `src/editor/commands.ts:200-207` (Enter at offset 0 inserts an Action row above any row, including a dialogue row under its cue); `src/application/writingSession.ts:176-186` (capture is awaited before `cadence.noteEdit`); `src/app/WritingView.tsx:611-625` (a failed `noteEdit()` only shows an alert).
- Scenario: open `INT. HOUSE - DAY\n\nJohn walks in.\n\nJOHN\nHello there.\n\nCUT TO:\n\nEXT. PARK - NIGHT\n\nThey sit.\n`. The skeptic mounted the real editor, sent real `keydown` events through `handleKeyDown`, and wired a real `WritingSession`, `SaveCadence`, `PersistenceController` and `ProtectedClose` to fake native ports. All seven edits were accepted with zero refusals, and each made `noteEdit` fail:

  | #   | Edit                                                 | Error            | Same edit on a force-marked source |
  | --- | ---------------------------------------------------- | ---------------- | ---------------------------------- |
  | 1   | Enter at end of the scene heading, then type `Dark.` | `round-trip`     | saves fine                         |
  | 2   | One letter on the blank row under a heading          | `neighbor-drift` | saves fine                         |
  | 3   | One letter on the blank row above a character cue    | `neighbor-drift` | saves fine                         |
  | 4   | Enter at the start of a dialogue line                | `round-trip`     | still fails                        |
  | 5   | Backspace the blank row under a heading              | `round-trip`     | saves fine                         |
  | 6   | Enter after `CUT TO:`, then type                     | `round-trip`     | saves fine                         |
  | 7   | Enter in the middle of a heading                     | `round-trip`     | still fails                        |

  In case 1, Enter alone stays capturable; the first typed character breaks it. Cases 4 and 7 are command bugs on any file, including ones Babel wrote itself.

- Consequence, measured: after the bad edit the skeptic typed in another row and waited 2.6 s (past the 2 s max-dirty limit): 0 checkpoints, 0 source saves, status "Changes pending". Explicit Save throws the capture error. `close.retry()` ends in `attention` with `onlyInMemory=true`. The control run with a harmless edit checkpoints, saves and closes normally. Deleting the offending letter resumes protection at once; typing elsewhere never heals it. The emergency copy falls back to a draft bundle that does contain the later text, but nothing in `src/` can import `babel-draft-copy-v1` (ADR 0027 says so).
- Why it matters: a crash loses everything typed since that keystroke (earlier work was already checkpointed and stays safe). The only signal is a codec error string that does not name the row. This is the content-protection invariant INV-06 (`SPEC.md:197`). It went unnoticed because every native drill source is force-marked (`.INT.`, `!`, `@` in `scene_moves.py`, `command_workflows.py`, `integrated_workflows.py`) and rows the app writes itself are always forced (`fountainCodec.ts:665-690`); the failure needs a file written by another tool or by hand.
- Skeptic verdict: SURVIVES WITH CORRECTIONS; could not refute. Three agents reproduced it independently (the correctness finder, the tests finder, and the skeptic for design position D-01, who found further throwing states: Backspace at the start of dialogue after a parenthetical, a two-row delete that removes the blank before a cue, typing ` ^` after a cue). Corrections: not critical, because nothing is corrupted and close stops rather than discarding. `docs/editor-behavior.md:50` and ADR 0027 do describe the uncapturable state generically as an accepted fallback; what is undocumented is that basic typing on standard Fountain reaches it. The finder's "about 10% of edits throw" figure (3,254 of 32,365) reproduces but comes from uniform random carets and 50% structural keys, so it is a census of 268 failing shapes, not a rate for real typing. Limits: plain typing was dispatched as ProseMirror's default `tr.insertText` in JSDOM; nothing was run in the native WebView.
- Fix sketch (untested): (1) in `replaceLines`, try the retained spelling first, then the forcing marker prefixed onto the retained source text (keeps indentation and scene-number bytes), then the generated spelling; (2) share the neighbour-widening loop with the same-row-count branch; (3) refuse Enter at offset 0 of a speech row, since dialogue has no forced marker; (4) make the right half of a mid-heading split an Action row; (5) add unforced-source key tests and the fuzz as a regression gate. The skeptic judged that the forced-spelling fallback does not break the untouched-bytes rule when bounded this way: `replaceLines` never runs without an edit, the re-spelled row is one whose grammar context the author just changed, and `SPEC.md:358` allows forced markers "when needed to prevent misinterpretation". Rejected: the finder's "trial-capture smart keys as paste does", which cannot cover cases 2 and 3 (plain typing never reaches `handleKeyDown`) and contradicts "capture/serialization stay off key handlers" (`docs/editor-behavior.md:138`). Independently of the codec fix, the D-01 skeptic recommended journaling a draft bundle whenever capture fails and naming the offending row in the message, so that no future uncapturable shape can stop protection (roughly a week, touches recovery, Tier 3).

### C-02 — A space at the edge of bold/italic/underline text makes the draft uncapturable; one common sequence leaves it stuck (high; M)

- Evidence: `src/domain/fountainInline.ts:279-288` (`sourceForInline` throws "Inline style boundaries cannot be represented unambiguously in Fountain" when a styled run starts or ends with whitespace); `src/editor/formatting.ts:39-47` (the collapsed-caret toggle only sets a stored mark, unvalidated; no `appendTransaction`); bound to Mod+B/I/U in `src/application/commandCatalog.json:131-153`; `docs/editor-behavior.md:94` documents "Empty selection toggles stored marks".
- Scenario, reproduced by the skeptic with a mounted `EditorView` and the real Ctrl+B keydown, then the real `WritingView` + session + cadence with the repo's fixture ports: Ctrl+B, type `Fast`, space → capture throws; the next letter heals it. But `Fast`, space, Ctrl+B off leaves it stuck, and Ctrl+B, space, `big` stays uncapturable however long the author keeps typing. In the stuck state, after 30+ more keystrokes and a click on Save: "Live version 40. Recovery: journaled version 7", no new checkpoint, no save.
- Why it matters: no recovery checkpoints and no source saves for any later typing anywhere in the script; a crash loses everything since the last good capture. The only feedback is one alert that does not say where the problem is. Separately, every multi-word bold phrase raises the same alert on the space, and the alert stays on screen after capture has recovered because `src/app/WritingView.tsx:613-624` never clears it on success.
- Skeptic verdict: SURVIVES WITH CORRECTIONS; could not refute, and wider than claimed (the leading-space case). Milder than permanent loss: in-memory text and undo are intact (Ctrl+Z restored capture), and close falls back to the draft-bundle emergency copy (`src/application/writingSession.ts:711-722`, read, not run). Caveat: JSDOM does not turn DOM mutations into transactions, so text input used ProseMirror's default `tr.insertText`; nothing was run in the native WebView. This run also demonstrates the consequence path that C-01 relies on.
- Fix sketch: in `sourceForInline`'s render (`src/domain/fountainInline.ts:~230-251`) move a group's leading and trailing whitespace outside the delimiters and emit whitespace-only styled groups unstyled; compare the round-trip against that normalised expectation; clear the capture alert on the next successful `noteEdit`. Existing bytes are not affected (the parser never produces a whitespace-edged styled group, and unchanged rows reuse prior text). Not quite a rendering no-op for underline: an underlined space is visible.

### C-04 — Clicking or moving the caret rewrites the manuscript file with identical bytes (medium; M, Tier 3)

- Evidence: `src/editor/state.ts:277-283` (the version that keys acknowledgements increments on `tr.selectionSet`; deliberate, because draft metadata carries selection anchors: ADR 0021, `docs/editor-behavior.md:46`); `src/editor/view.ts:86-87` → `src/app/WritingView.tsx:605-616` (only `findNavigation` is exempt) → `src/application/writingSession.ts:176-186`; `src/application/saveCadence.ts:240-250` (`sourceNeeded` is true on `version > fileSavedVersion` alone; rolling snapshots dedupe by hash at `:324`, source saves do not); no content check in `src/application/persistenceController.ts:199-281` or `src-tauri/src/persistence_host.rs:191-229`; `crates/screenwriter-core/src/documents/source_store.rs:254-257` (the only no-replace path is a same-version duplicate; the old bytes read at `:312` are never compared with the request, so the full transaction runs, `:318-476`).
- Scenario: open a writable file and click once. The skeptic's mounted-app test (real `WritingView` and ProseMirror view, fake ports) printed: idle 3.2 s → 0 saves, 0 checkpoints; caret move 1/2/3 → saves 1/2/3, checkpoints 1/2/3, `sameBytes=true`, about 0.8 s after each move; read-only session → nothing. Because `prime()` sets `dirtySince` at open (`saveCadence.ts:104`), the first caret move more than 2 s after open saves immediately (58 ms). A never-edited file is rewritten by the first click.
- Why it matters: new inode and mtime on every caret pause, with three manuscript-sized writes plus fsyncs; a file that is merely being browsed is exposed to the interrupted-save states; and the single retained `previous` generation is overwritten with bytes identical to current (`source_store.rs:343-359`), so after any click it no longer holds distinct earlier content (`SPEC.md:638`). Contradicts the M3-10 acceptance line "unchanged source avoids replacement" (`docs/tasks/M3-10.md:28`) and `SPEC.md:379` ("Prefer not writing at all for a no-op"). No ADR justifies it.
- Skeptic verdict: SURVIVES WITH CORRECTIONS; no guard exists at any layer. Reproduced in the mounted frontend; the Rust side was read, not run. A second skeptic (D-06) confirmed it independently and noted the header status also flips to "Changes pending"/"Saving" on every caret move. Severity medium: no byte loss, replacement is atomic.
- Fix sketch: a native no-replace acknowledgement. In `save_next_with`, after the baseline check at `source_store.rs:312-317`, if the old bytes equal the request: fsync as the duplicate branch does, return a `SaveReceipt` for the new version with the unchanged fingerprint. The frontend already accepts a receipt whose fingerprint did not change (`src/application/persistenceState.ts:238-290`). About 20 lines of Rust plus a test and the Tier 3 matrix. The skeptic rejected the finder's alternative (carry the saved version forward in `sourceNeeded`): it mints file-saved credit without a receipt, which breaks INV-05/INV-10. Optional: have `prime()` not start the dirty clock.

### C-03 — Typed `[`, `]`, `_` and `\` are saved as backslash escapes that the PDF prints literally (medium; S for the encoder, M for the renderer side)

- Evidence: `src/domain/fountainInline.ts:257` (`replace(/[\\*_[\]]/g, '\\$&')`), reached from `src/editor/sourceBridge.ts:103-107`; bundled Screenplain honours only `\*` (`richstring.py:234-242`); nothing unescapes before rendering (`tools/pdf-helper/frozen_profile.py:239-259`; `src-tauri/src/publication_host.rs:483-485` pipes raw source to the helper).
- Scenario: typing ` [O.S.]` saves `!He walks. \[O.S.\]`; `to_do` saves `to\_do`; `a\b` saves `a\\b`; typed `[[note]]` saves `\[\[note\]\]`. An existing line `He reads [the sign] aloud.` opens as a normal row, and one keystroke on it saves `!He reads \[the sign\] aloud. x`. The skeptic rendered a sample through the built helper and ran `pdftotext`: the PDF contains `He walks. \[O.S.\]`, `to\_do`, `a\\b`, and `\_this\_` came out as `\this\` with an underline. Script Check and the export assessment return no issues; the assessment marks the export "verified".
- Why it matters: author text is altered in the portable file and in the PDF with no warning. Babel reopens its own escapes cleanly, so the writer never sees the problem in-app.
- Skeptic verdict: SURVIVES WITH CORRECTIONS; could not refute. Narrowing: only the edited row is rewritten (no-op saves and edits on other rows preserve bytes); the added `!` is the codec's general behaviour for any edited action row, not part of this defect; rows with an unpaired `_` open as literal rows and are saved without escapes. fountain.io sanctions `\*` and `\_` only; `\[`, `\]`, `\\` are Babel-only spellings. `tests/contract/fountain-complex.test.ts:655-671` pins `\*`, `\_`, `\\` as codec output; nothing pins brackets. `docs/document-model.md:77` admits the interoperability gap as an open item with no TODO. Brackets such as `[beat]` are occasional in screenplays; underscores and backslashes rare.
- Fix sketch: encoder (S): escape `[`/`]` only where `[[` or `]]` would form, and `\` only before an escapable character; update the pinned test. Renderer (M): `\_` cannot simply be dropped from the encoder because unescaped pairs underline; either extend the helper's unescape for `\_`, `\\`, `\[`, `\]` in `frozen_profile.parse` (changes the profile hash and pins) or add an SC005 issue for escapes the renderer cannot honour.

### C-05 — On SELinux-labelled filesystems every save, Save As, PDF export and snapshot would fail (medium; S code, M with a Fedora check)

- Evidence: `plain_metadata` at `crates/screenwriter-core/src/documents/source_store.rs:627-632` rejects any non-zero `flistxattr` size; called on the source and candidate (`:308, :378, :398, :399`) and also gating the Save As destination (`save_as_store.rs:52`), PDF export (`pdf_store.rs:30, 42`), snapshots (`snapshot_store.rs:750, 823`) and choices. Open has no xattr check (`linux.rs:457-520`), so the document opens writable.
- Scenario: on Fedora/RHEL-style hosts every file lists `security.selinux`. The document opens writable; every save then returns `saveNeedsAttention` with the text "Saving needs attention before the next source save." and no cause; the offered remedy `ReopenOrSaveCopy` fails for the same reason. Only recovery journals work. No data loss (the repo's own test confirms the journal still holds the draft).
- Skeptic verdict: SURVIVES WITH CORRECTIONS. Not natively tested (the audit host is Arch without SELinux); the SELinux half rests on sources: a kernel SELinux maintainer's April 2025 LSM-list patch stating SELinux returns `security.selinux` in `listxattr()` for all inodes, and Python tracker reports of unprivileged `os.listxattr` returning it. Sub-claim "files tagged by browsers cannot save" is REFUTED for mainstream browsers (Chromium stopped writing `user.xdg.origin.url` in 2019; Firefox never did); remaining `user.*` triggers are `curl --xattr`, KDE tags, `setfacl` (ACLs are in the same list; `crates/screenwriter-core/tests/source_save.rs:431` asserts rejection). Related, confirmed in code: a 0664 file or 0775 parent directory makes the document view-only (`linux.rs:868-872`), with the UI saying only "The source is open read-only."; Fedora and Ubuntu default to umask 0002. That is a deliberate ADR 0012 policy. ADR 0014 documents xattr rejection as deliberate; SELinux is mentioned nowhere, so the consequence is unrecognised rather than a documented exclusion. Becomes high if Fedora/RHEL is declared a release target.
- Fix sketch: read the xattr name list instead of probing its size and exempt `security.selinux` (the kernel labels the new inode; copying it is typically denied). Keep rejecting ACLs and unknown namespaces. Surface the cause in the UI. Update ADR 0014.

### D-01 — The single-Enter writing flow produces Fountain that other parsers (and Babel's own PDF pipeline) misread; the row-per-source-line model makes ordinary edits refusable (impact high)

- Current design: `SPEC.md:420-438` (Enter table), `:381`, `:397-401`; ADR 0007; `src/editor/schema.ts:27-34` (`doc: line+`, one node per source row, blank lines are real empty `action` rows); `src/editor/commands.ts:237-255` (Enter adds the next row with no separator).
- What the skeptic confirmed, driving the mounted editor's real `handleKeyDown` (`src/editor/view.ts:170-246`) and parsing with the bundled Screenplain 0.12.0:
  1. Typing heading, Enter, action, Enter, Tab to cue, Enter, dialogue… from an empty document saves `.INT. KITCHEN - DAY\n!Maya enters.\n@MAYA\nHello there.\n@JON\nHi.\n!They sit.\n`. Screenplain reads it as one `Dialog` whose character is `.INT. KITCHEN - DAY`; the app's own export assessment reports three blocking SC005 issues. Forced markers do not replace blank lines.
  2. In an opened idiomatic file, one Enter after dialogue then an action saves `MAYA\nHello there.\n!She leaves.`; Screenplain absorbs the action into Maya's speech.
  3. Select-all or whole-speech Backspace/Delete, type-over, Cut and Shift+Enter are refused (27 `refused(` sites in `commands.ts`); Shift+Enter is refused everywhere although `SPEC.md:462` permits refusal only where a break is unproven. A line with an inline note opens as a protected `raw` row; typed `[[note]]` saves as `\[\[note\]\]`; dual dialogue cannot be authored (no caller of `setDualDialogue` outside `src/domain`).
- Skeptic corrections: pressing Enter twice does produce correct, exportable Fountain (Enter on an empty action row adds a real blank line, `src/editor/sourceBridge.ts:95-100`), so "a from-scratch draft is not portable" is too broad: the failure is the documented single-Enter flow. The failure is visible (export is blocked), not silent, and all text stays in the file. Backspace is refused only on the first dialogue line directly after a non-empty cue (`commands.ts:319-324`). Standalone note rows are editable.
- Skeptic verdict on the redesign (element-level schema, serializer owns separators and "always succeeds"): SURVIVES WITH CORRECTIONS, as a direction only. "Stage 1 in days" is refuted: the one-row-per-line mapping is relied on by `sourceBridge.ts:371-378, 412`, `src/application/editorMetadata.ts`, scene moves, find, outline, clipboard and recent position (16 files), and `SPEC.md` §05.5 requires intentional blank lines to stay authorable. A "total serializer" is unachievable as stated (Fountain cannot represent some states); the honest contract is "kind may degrade with a diagnostic; text is always journaled". Un-forcing markers is cosmetic and adds risk. The byte-preservation argument for untouched elements could not be refuted.
- A second skeptic (D-07) independently reproduced item 1 and confirmed the limitation is pinned as expected by tests (`src/domain/exportAssessment.ts:243-245`, `tests/contract/export-assessment.test.ts:278-296`).
- Change sketch (smallest fix, 1–3 days by the skeptic's estimate): have `enter()` (`commands.ts:237-253`) insert the empty separator row when starting a new paragraph, with a symmetric Backspace; double-Enter proves the codec, assessment and Screenplain already accept that state. Includes re-pinning `tests/contract/editor-keys.test.ts:64-100` and the native input drills. Tier 2. Separately (medium): allow deleting a speech / select-all, hard breaks where provable, editable inline-note lines, dual-dialogue authoring (see S-08). The element-level schema is a post-V1 option, not a prerequisite. The related content-protection defect (capture failure stops journaling) is listed under Correctness as C-01.

### D-02 — Every reopen of an edited script leaves the writer typing unprotected until they find and click "Keep Current File" (impact high; M)

- Current design: ADR `docs/decisions/0017-explicit-recovery-choices.md:29-34` ("A restart requires a fresh choice; reconciliation is never persisted"). A fresh `session_id` per open (`crates/screenwriter-core/src/documents/linux.rs:519, 557`) fails every checkpoint and save at `recovery_store.rs:209`; Keep only sets the in-memory `recovery_reconciled` flag (`choices_store.rs:468`, `linux.rs:251-254`). The only `keep` caller is the panel button (`src/app/RecoveryChoicePanel.tsx:293`). The native drill performs the ritual on the happy path (`tests/native/writing-lifecycle/drill.py:406-412`).
- Skeptic: factual claims CONFIRMED, and worse than claimed. Typing is not blocked: the writer keeps typing while every checkpoint and save fails with no auto-retry (`src/application/saveCadence.ts:11-14`), sees only "Save failed" (`persistenceState.ts:350-368`), and at close is told "Newer changes exist only in memory" (`protectedClose.ts:107`); "Close with this risk" then loses the session. So the current design is itself a loss path. A normal reopen mounts up to three panels (candidates are unfiltered, `startup_reader.rs:119-150`), two of which offer "Recover as Current" for an older, superseded generation. Journals are bounded (two records plus one `previous`), not growing. The silent-reconcile rule does not contradict `SPEC.md:654` ("newer/different"); only ADR 0017 needs amending.
- Proposed rules and their verdicts:
  1. Auto-reconcile when the journal content equals the file: SURVIVES WITH CORRECTIONS. No loss path found. Do it natively at open, exclusive registrations only, latest generation only, clean inspection, and only when transaction state is `NoTransaction` or `ConfirmedRecordMatchesSource` (after a crash post-rename the hashes match but an intent remains, and the hidden panel holds the only "Resolve Interrupted Save" button, `RecoveryChoicePanel.tsx:333`).
  2. Auto-adopt a journal that descends from the current file: REFUTED as automatic. Unsafe case: a save to A fails, the writer uses Save As to B (A's journal is untouched, `save_as_store.rs:3-4`), later opens A, and the redirected work is auto-written into the file they chose to leave alone. Also refuses after a prepared-intent crash (`choices_store.rs:390`), has no persisted decision, and contradicts `SPEC.md:654`.
  3. Plain-language choice on true divergence: SURVIVES WITH CORRECTIONS. Define divergence by content hash, not the full fingerprint (copy/restore/sync change inode and ctime with identical bytes); keep "Save Recovered Copy" (the only action for malformed UTF-8 or a missing source, `choices_store.rs:339-342, 476`); persist the Keep decision.
  4. Retire journals after a confirmed save and clean close: REFUTED. It is the only rule that destroys bytes: `'closed'` is published by retry, emergency copy and accept-risk alike (`protectedClose.ts:176, 232, 254`); save v5 confirmed, v6 checkpointed, save fails, "Close with this risk" → retirement deletes the only copy of v6. It is also unnecessary once rule 1 runs at open.
- Change sketch: (1) native reconcile at open when the latest clean journal record is byte-identical to the source and no save transaction is unresolved; (2) show only the latest generation, older ones behind "Inspect"; (3) when recovery differs, one prominent plain-language prompt before editing (Restore / Keep saved file / Save copy), no auto-adoption, decision persisted as a marker; (4) leave journal retirement to a retention task, native and hash-verified at deletion time. Items 1–2 are a few days (native fast path, panel filter, rewriting restart assertions at `crates/screenwriter-core/tests/source_save.rs:382` and `recovery_choices.rs:301`, nine native runners, Tier 3 matrix); item 3 is a further M.
