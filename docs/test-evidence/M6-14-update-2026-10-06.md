## What was actually read back

  Save As, edits and saves it. New package reopens it writable and saves
  exactly. BOM, CRLF, meaningful trailing spaces, unknown title key, note and
  omission survive. Original/current sources are 138/146 bytes with SHA-256
  `7e988fd7…` / `21de7ed2…`.
- **Snapshot/history**: old package creates a named snapshot, restores it and
  Undoes, producing real safety/history material. All old snapshot/history
  files are intact before new writing. New package restores that old named
  snapshot; Save/Undo/Redo/Undo each independently match literal bytes.
  Original snapshot files and history objects/safety refs remain intact.
- **Recovery**: old package writes and protects an unsaved Action draft, then
  closes with recovery retained. New package resumes the exact old document
  and generation into a fresh draft and saves its 26 literal bytes
  (`b8a29130…`). The original journal remains byte-identical.
- **Preferences**: Dark, 125% zoom and typewriter scrolling are set through
  the old UI. The new WebView reads the identical stored preference value;
  screenshots also show those controls retained.
- **Dictionary**: the old package has no provider, so it cannot Add via
  spelling review. A labelled, checksummed schema-1 `Zøëvexia` fixture is
  seeded before launch. The old package's preferences UI reads it and
  durably republishes it through Off/On (generation 3). New package reads
  that exact generation, reports one added word, ignores `Zøëvexia` and
  detects the deliberate `helllo` misspelling. No host personal dictionary
  or provider injection was used. This is native reader/writer compatibility
  for a fixture, not an old-package Add pass.
- **Unknown newer schema**: a schema-999 managed project opens view-only,

  Original source and future metadata stay identical. Separately, a
  schema-999 install record makes install/status/uninstall refuse; all

- **Update/uninstall**: installation changes no source, native app-data or
