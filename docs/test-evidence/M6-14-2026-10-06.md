## Findings

1. **Packaged spellcheck never worked (fixed).** The package showed "No
   offline dictionary for en_US" on a host with every spelling package
   installed. A direct probe of the same library bytes: the host
   `libenchant-2.so.2` lists the Hunspell provider; the copy inside the AppDir
   lists none. Enchant finds provider modules beside its own file and the
   bundle had no `enchant-2/`. Earlier spellcheck passes all used the
   unbundled release binary. Fix: the build stages the provider and its
   Hunspell library into the package ([ADR 0045](../decisions/0045-user-install-and-packaged-spelling.md)).
2. **Save pickers opened in the read-only package folder (fixed).** A package
   runs with its working directory at `<mount>/usr`, which its bundled WebKit
   needs. A Save As given only a filename ended with "The selected destination
   is unavailable or unsafe"; recovery stayed protected and nothing crashed.
   This confirms the open observation in the [earlier pilot](PILOT-2026-10-06.md).
   Fix: every native picker starts in the home folder.
3. **GLib rejects a desktop entry whose program path contains `%`**, even
   escaped as `%%`. The installer refuses such an install folder before
   writing anything.

## CI and the relocatable-Enchant requirement

The first push (`a6cbfc0`, run 37469251505) passed every existing step and
failed only the new package check: the Enchant that CI builds from source
loaded the provider from its own install prefix, not from the package. An
upstream default build is not relocatable; the host's distribution build is.
A package from such a build would have had spellcheck only where that prefix
exists. `tools/ci-enchant.sh` now configures `--enable-relocatable`, and
staging proves relocation on a copy before the package is built.

| Local check of `tools/stage-spellcheck-provider.py` against        | Result                                              |
| ------------------------------------------------------------------ | --------------------------------------------------- |
| Host Enchant 2.8.21 (Arch)                                         | Staged; relocation proven                           |
| `bash tools/ci-enchant.sh <dir>` build, now `--enable-relocatable` | Script's own probes pass; staged; relocation proven |
| Same source, default configure (what CI had)                       | Refused with the explanation, as CI showed          |

A rebuild through the updated staging step gave the same packaged executable

## Installed launch

`installed_launch.py` used a fresh home `…/Zoë Writer` with data in
`My Data é` and the package in `Apps é/babel`, and an environment holding only
the live compositor/session addresses and `PATH=/usr/bin`.

- `desktop-file-validate` accepted the entry; `gtk-launch babel-desktop`
  resolved it by name through GIO and started the package.
- The window class `babel-desktop` equals the entry's `StartupWMClass`. The
  executable is `/tmp/.mount_babel_…/usr/bin/babel-desktop` on `fuse`; the
  launcher's directory was the home folder; no automation variable; no
  development PATH entry; no internet socket owned by the app or its helpers.
- The screenshot shows Home with "babel 0.0.1 · native desktop host connected"
  and no recent screenplays (inspected).
- An ordinary compositor close ended every owned process, the mount was
  released, and the crash journal for that window has no event.
- Uninstall removed exactly the entry, package and icon; app data stayed;
  `gtk-launch` then failed to find the entry. The owner's own applications
  folder had no babel entry before or after.

Installing the final package over the picker-fix one in the runner's profile
kept both package files and repointed the entry (two real packages).

## Limits

- One host and distribution. The no-dictionary case hides the folder from the
  app; no host without spelling packages or another distribution was used.
  Only `en_US`.
- Desktop-entry launch is checked through GIO's launcher, not by clicking in
  the owner's launcher, and that run is not network-isolated: FUSE cannot
  mount inside the unprivileged namespace. Offline writing is the runner's
  evidence; the desktop run records no internet sockets.
- The app has no file-open argument, so there is no file association.
- Manual update with real app data from a previous package, unknown-newer
  refusal, and release notices for the bundled libraries are not done.
- The full native matrix, tmpfs/Btrfs workspace matrix and differential gates
  were not rerun locally: no capture, codec, persistence or frontend change.
  CI ran its usual workspace, differential and package steps.
- Same agent wrote and reviewed this; not independent sign-off.
