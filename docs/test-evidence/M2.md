## M2-02 — Recovery checkpoint format

Date: 2026-09-28 PDT. Branch: `M2-02-recovery-checkpoints`. M2-01 committed
as `7e1ea90` and fast-forwarded into local main at owner request before this

### Deliverable and acceptance coverage

Native-only complete-source recovery with version-1 framed/checksummed
records, document/session/version/generation/hash/base fingerprint and opaque
JSON draft metadata. Exact recovery-only receipts follow native verification,
file/directory sync and publication; source bytes/files are never rewritten.
Managed checkpoints live in `.screenwriter/recovery/`; loose/unsaved checkpoints
in private app data. See [ADR 0013](../decisions/0013-recovery-checkpoint-journal.md).

- Seven format/property tests cover independent header layout and known SHA-256,
  raw bytes/draft metadata, every truncation and one-byte mutation in a second
  frame, malformed buffers, unknown/oversized/nonmonotonic records, bounds and
  source-hash validation even when a frame checksum is recomputed.
- Five native unit-test entries cover the 15-stage fault matrix (candidate and
  predecessor write/sync/publication and acknowledgement), simulated ENOSPC,
  lost ownership, conflicting overlaps/unknown schema and six native SIGKILL
  barriers. The `crash_child` helper entry is a no-op in the normal parent run;
  its stage assertions/operations execute only in explicitly spawned children.
- Twelve native API tests cover named/unsaved/managed checkpoint/restart,
  source/base fingerprint and draft fidelity, exact/idempotent receipts,
  stale/conflicting versions, forged/cross-session requests, hash mismatch,
  torn/corrupt quarantine and predecessor fallback, external edit/delete
  independence, unsafe paths/released handles, future/oversized records and
  a physically oversized journal without truncating it into quarantine.
  The final API test measures fixed growth over 32 large checkpoints.

No checkpoint IPC, mocked-success recovery, native WebView recovery UI,
source-file save, startup adoption or global retention is added. Process kill
leaves OS caches alive; injected I/O/disk-full errors are simulation and are
not hardware power-loss or actual host-disk exhaustion proof.

## M2-03 — Serialized source replacement

Date: 2026-09-28 PDT. Branch: `M2-03-serialized-source-replacement`.
Host: Linux 7.2.5-3-omarchy x86_64, Rust/Cargo 1.97.1, Node 26.7.0,
pnpm 11.22.0; `/tmp` tmpfs and workspace Btrfs. Synthetic owned directories
only; no personal manuscript, credentials, remote, privileged package, global
configuration, dependency or permission capability was used/added.

Deliverable: bounded immutable per-document FIFO, recovery-first native source
transactions, fingerprint/ownership checks, independent previous source,
exclusive random same-directory candidate, full write/sync/verify/rename/directory
sync, inode-lease/baseline transition, exact source receipts, typed uncertainty
and read-only restart inspection. [ADR 0014](../decisions/0014-serialized-source-replacement.md)
records the contract and bounds. Source saves remain headless/native-only.

### Acceptance coverage

`crates/screenwriter-core/tests/source_save.rs` has nine public native API
entries: byte-exact BOM/CRLF/whitespace/unknown/incomplete Fountain no-op;
separate source/recovery receipts; immutable initial snapshot and updated
checkpoint baseline; same-version checkpoint reflush after source save;
FIFO/owned snapshot behavior, eight-request and 32 MiB cross-document budget,
fixed artifact count after eight saves; version/session/hash/encoding/metadata/
fingerprint rejection; external divergence retaining external and local bytes;
delete/move/parent permission failures; private managed storage and unchanged
unknown project metadata; restart observation and older-session blocking;
view-only/unsaved source-save refusal with independent malformed raw recovery;
real user xattr and POSIX access ACL rejection retaining exact attribute bytes.
ACL test layout/tags were independently checked against installed Linux UAPI
`posix_acl_xattr.h` and `posix_acl.h`, not generated from the implementation.

Eleven source transaction unit entries include a child harness. They exercise
ordinary owner/group/0640 mode, native baseline and old/new inode lease
transition (including direct old-lease release/new-lease contention), independent
previous copy versus in-place mutation, exact duplicate fresh verification,
conflicting/stale/retry identity across a failed attempt, and recovery-failure
isolation. The 20 injected source stages span recovery receipt, intent/previous/
candidate partial writes and syncs, previous publication, final check, rename,
directory sync, verification and confirmed publication. Every stage returns
failure, retains whole old/new source and recovery, and retains the old source
independently whenever replacement happened. Injected ENOSPC is simulated disk
full, not actual host exhaustion. Permission loss, directory substitution,
corrupt/future/unsafe/pending artifacts, and external edits before/after rename
are also tested. Unconfirmed replacement blocks further saves and bare release,
while newer independent raw checkpoints remain writable.

Eight pipe-barrier SIGKILL stages are native process-interruption evidence:
partial intent, partial previous, published previous, partial candidate, synced
candidate, source replaced, directory synced and confirmed metadata published.
After restart the source is the whole old/new generation, recovery contains the
requested bytes, and any replaced source has the independently readable old
copy. Partial candidates are inspected, never promoted; a partial intent is
attention. Child environment variables/gates exist only in cfg-test binaries.
A healthy recovered frame/confirmed file never establishes receipt delivery.

Five native worker entries test eight-job/32 MiB admission and permit release,

different request's preexisting FIFO entry. The poison test deliberately catches
