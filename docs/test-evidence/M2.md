## M2-01 — Identity and safe open

Date: 2026-09-28 PDT. Branch: `M2-01-identity-safe-open`.
Host: Linux 7.2.5-3-omarchy, x86_64; Node 26.7.0, pnpm 11.22.0,
Rust/Cargo 1.97.1. `/tmp` is tmpfs; repository filesystem is Btrfs.
Only generated synthetic directories were used; no personal manuscript,
credentials, global setting, privileged package or remote destination was used.

Deliverable: native-only selected paths, random opaque document/session
identities, exact immutable source bytes and native disk fingerprints,
private persistent loose identity records, conservative managed metadata,
cooperating ownership leases, structured errors and strict path-free IPC.
See [ADR 0012](../decisions/0012-native-document-identity.md).

### Acceptance coverage

`crates/screenwriter-core/tests/safe_open.rs` exercises actual native file
operations: BOM/CRLF/meaningful whitespace/unknown syntax/empty source exact
bytes and no-op source mtime/mode preservation; independently known `abc`
SHA-256; malformed UTF-8; read-only source/directory; missing/unreadable/large
source; directory/FIFO rejection without blocking; source/parent/store/project
symlinks; traversal/relative paths; hard links and unsafe/special modes;
persistent loose identity across restart/replacement and independent copies;
corrupt/future registry preservation; managed/unknown-field metadata;
invalid/future/duplicate/unsafe metadata; unrelated loose source and renamed
managed mapping candidate; same-process and independent-process contention;
duplicate managed UUIDs; revoked/forged/cross-session handles; unsaved identity
and capacity bound; edit/replace/delete/chmod/symlink divergence; moved source
parent/store and replaced lock inode; changed managed identity. The immutable
initial source remains available after external divergence.

The child-process test execs the compiled test binary with `PATH=/nonexistent`
and confirms the parent lease still owns the synthetic source. The
`ownership_child` harness entry is a no-op during the ordinary suite; its
assertions run in that explicit child invocation.

`src-tauri/src/document_ipc_tests.rs` dispatches through **Tauri MockRuntime**:
exact raw bytes, typed errors, cross-session rejection, extra-path rejection,
no write/open-by-path command, revocation, and honest uninitialized production
state. This is IPC contract evidence, not native WebView E2E.
`tests/contract/document-ipc.test.ts` mocks `invoke` to verify frontend
identity-only forwarding, raw byte retention and failure propagation.

### Corrections and limits

Initial `cargo test -p babel-desktop --locked` correctly refused the changed
dev-dependency lock; rerunning without `--locked` updated Cargo.lock. All final
checks use the resulting lock. Initial Clippy failed on a test's non-octal
permission literal; corrected to `0o0`. Initial `pnpm check` and `pnpm test` failed on two
frontend failure tests because `beforeEach(() => invoke.mockReset())` returned
the mock as a cleanup function, calling it again after each test. Context7
confirmed the cleanup contract; the hook now uses a block without returning
the mock. The original-object rejection assertions remain. These were failed checks,
not passes; final reruns are recorded above.

No source save, journal/checkpoint, recovery-available status, editor, parser,
history/remote integration or PDF operation is added. Native selection UI and
real WebView manuscript opening remain unwired. ACL/xattr ownership policy,
foreign-owner fixtures (without privilege), network/external/sync filesystems,
hardware power loss and other platforms are unverified. Btrfs/tmpfs results
only close the bounded Linux M2-01 task, not M2 exit or product adoption.
M2-02 is next after review.

## M2-02 — Recovery checkpoint format

Date: 2026-09-28 PDT. Branch: `M2-02-recovery-checkpoints`. M2-01 committed
as `7e1ea90` and fast-forwarded into local main at owner request before this
task. Same recorded Linux host/toolchains as M2-01. Synthetic test roots are
random children of tmpfs `/tmp` or the Btrfs repository and removed on completion.
No personal source, credential, global setting, cloud resource or remote push.

### Deliverable and acceptance coverage

Native-only complete-source recovery with version-1 framed/checksummed
records, document/session/version/generation/hash/base fingerprint and opaque
JSON draft metadata. Exact recovery-only receipts follow native verification,
file/directory sync and publication; source bytes/files are never rewritten.
Managed checkpoints live in `.screenwriter/recovery/`; loose/unsaved checkpoints
in private app data. See [ADR 0013](../decisions/0013-recovery-checkpoint-journal.md).

- Seven format/property tests cover independent header layout and known SHA-256,
  raw bytes/draft metadata, every truncation and one-byte mutation in a second
  frame, malformed buffers, unknown/oversized/nonmonotonic records, bounds and
  source-hash validation even when a frame checksum is recomputed.
- Five native unit-test entries cover the 15-stage fault matrix (candidate and
  predecessor write/sync/publication and acknowledgement), simulated ENOSPC,
  lost ownership, conflicting overlaps/unknown schema and six native SIGKILL
  barriers. The `crash_child` helper entry is a no-op in the normal parent run;
  its stage assertions/operations execute only in explicitly spawned children.
- Twelve native API tests cover named/unsaved/managed checkpoint/restart,
  source/base fingerprint and draft fidelity, exact/idempotent receipts,
  stale/conflicting versions, forged/cross-session requests, hash mismatch,
  torn/corrupt quarantine and predecessor fallback, external edit/delete
  independence, unsafe paths/released handles, future/oversized records and
  a physically oversized journal without truncating it into quarantine.
  The final API test measures fixed growth over 32 large checkpoints.

No checkpoint IPC, mocked-success recovery, native WebView recovery UI,
source-file save, startup adoption or global retention is added. Process kill
leaves OS caches alive; injected I/O/disk-full errors are simulation and are
not hardware power-loss or actual host-disk exhaustion proof.

active records plus one predecessor; failures/quarantine preserve bounded
artifacts and block unsafe cleanup. No timing assertion is used as a flaky
test gate; measured release/debug performance is recorded independently.

### Corrections and open limits

Initial Rust formatting rejected a non-ASCII hex escape in a synthetic string;
the test now appends the raw byte to a byte buffer. Initial Clippy rejected two
collapsible conditionals; corrected without suppressing lint. Review also added
a physical oversized-file guard (never copy only a bounded prefix into
quarantine), conflict detection for overlapping prior generations, native base
fingerprints, predecessor-stage fault/kill coverage and removal of redundant
hashing of the same read buffer during stat comparisons. Final checks use the
resulting code. No check was disabled or permission expanded.

Production integration is still Linux-only. Native/UI checkpoint scheduling,
serialized source saving, UI stale receipts, startup choice/adoption, pending
and quarantine resolution, orphan retention/protected close, power loss and
Tier 1 packages/platforms remain open. Earlier-session recovery intentionally
blocks new-session writes pending M2-05 reconciliation. Same-disk safety copies
are not disaster backups. Next: M2-03 Serialized source replacement.
