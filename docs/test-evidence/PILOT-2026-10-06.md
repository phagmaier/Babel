## Findings (writer experience, not data safety)

1. **Editor below the fold.** About ten rows of controls (theme, zoom, status,
   command palette, 15 action buttons, element picker, help) sit above the
   writing surface; at the default 900×680 window the editor is not visible.
2. **Engineer-facing recovery.** Home lists "Published journal · Version 75,
   generation 4 · 84 bytes" with SHA-256 values; a writer needs time, first
   lines and one primary action.
3. **New screenplay starts in Action.** Typing `INT. …` stays Action by design
   (SPEC S07.1 forbids automatic reclassification); Tab twice selects Scene
   Heading. A first-row Scene Heading default would match common practice.

## New screenplay and identical suggestions (finding 3, plus a new finding)

- A zero-byte or BOM-only document's placeholder row is a Scene Heading
  (`src/editor/state.ts`); Mod+2 makes it Action. Four native drills that
  type Action into a new screenplay now press Mod+2 first.
- New finding while typing: after `INT. FERRY TERMINAL - DUSK` the time
  suggestion `DUSK` equalled the typed text, and Enter "accepted" it without a
  change, so the next line ran into the heading. SPEC S07.6 now says an
  identical suggestion is no acceptance: Enter/Tab dismiss it and act normally
  (`completionChangesText` in `src/editor/completion.ts`). Case changes,
  completions and prefix spacing still consume the key.
