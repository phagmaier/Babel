## WebKit/JSC and graphics dependencies, separately

WebKit and JSC 4.1 are shipped together in this Arch package, not separate JSC
runtime packages. The package provides both `.so=0-64` identities; its recipe
uses GTK 3 and libsoup 3 (`USE_GTK4=OFF`, `USE_SOUP2=OFF`). The
[API migration documentation](https://webkitgtk.org/reference/webkitgtk/stable/migrating-to-webkitgtk-6.0.html)
distinguishes 4.1/GTK 3 from 6.0/GTK 4. The candidate therefore addresses the
recorded API family; equal SONAMEs do not prove an operationally compatible drop-in.

Candidate `.BUILDINFO` records Mesa `1:26.2.4-1`, libdrm `2.4.134-1`, glibc
`2.44+r50+g1848099f063e-1` and libglvnd `1.7.0-3`. The first three match R5's
frozen package versions. GTK is `1:3.24.52-2`, versus frozen `-1`; the build also
uses GLib `2.90.0-1` and libsoup `3.6.6-2`. Testing metadata routes several
dependencies into testing. Build dependencies are provenance, not a verified
complete host upgrade plan. No mixed stable/testing substitution is approved.

[Mesa extra](https://archlinux.org/packages/extra/x86_64/mesa/) and
[libdrm extra](https://archlinux.org/packages/extra/x86_64/libdrm/) currently
publish those frozen versions. Gallium, `libgbm` and `dri_gbm` belong to Mesa;
libdrm has its own package/debug identity. The reviewed patch is WebKit-side EGL
lifecycle code, not a demonstrated Mesa/libdrm package correction. No graphics
upgrade or graphics-origin attribution is inferred from its description.
