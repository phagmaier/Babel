## R03 — Uncapturable newer draft is labeled saved and cannot be copied

Priority: **high; required correction**. Owner:
[M3-12-R1](../tasks/M3-12-R1.md). SAVE-01/02/05; INV-03/05/10/11.

Open `@MAYA\n(softly)\nHello.\n`, place the caret after `(sof`, explicitly
save, then press Enter. The editor accepts two Parenthetical rows `(sof` and
`tly)` and retains the Dialogue. The codec correctly refuses capture because
the second row is not a valid Parenthetical. Disk and journal retain exactly
the original generation; none contains the latest two-row draft.

The production protection status nevertheless remains **Saved locally** for
the earlier version. Retry close fails; selecting a real native copy destination
and choosing Save Emergency Copy and close also fails. The close panel says
“The source is saved, but close could not be confirmed.” That assessment is
based on the old controller version and understates the risk of the newer
in-memory draft. No safe copy of those live rows is produced.

The causal path is [WritingView](../../src/app/WritingView.tsx)'s asynchronous
`changed` observer → [WritingSession.noteEdit](../../src/application/writingSession.ts)
→ [EditorCaptureBoundary](../../src/application/editorCapture.ts). A failed
capture never advances the persistence controller's view of the live editor.
Status and [ProtectedClose](../../src/application/protectedClose.ts) assess
that older version; emergency copying calls the same failing capture.
[copyEditorDraft](../../src/editor/sourceBridge.ts) exists but is not connected
to a default-app preservation action. Existing codec refusal/derivative tests
do not verify production status and copying in this failure state.

Fix immediate live-version status independently of successful hashing/capture,
and supply an accurately labeled, bounded native-selected preservation route
for all latest live rows/styles plus exact original source. Do not silently
normalize the split to make saving pass. Close remains conservative until exact
protection or a current, accurately informed risk decision exists.

## R02 — Unsaved checkpoint has no actionable restart recovery route

Priority: **high; required correction**. Owner:
[M3-09-R1](../tasks/M3-09-R1.md). SAVE-03/05; DOC-01/02; SPEC S10.5.

New → type → Protect draft → independently audit the acknowledged journal →
kill only the owned app → restart. The unsaved checkpoint survives and its
exact text is inspectable in the default home screen. Its source bytes are not
lost from disk. However, the only checkpoint action is Inspect; there is no
resume/adopt/export action. New allocates a different blank identity and Open
requires an existing source file. There is no original source for this draft.

[App](../../src/app/App.tsx) accepts only `new`/`picked` opens;
[RecoveryReview](../../src/app/RecoveryReview.tsx) implements read-only
inspection. Its [preview](../../src/application/startupRecovery.ts) is bounded
to 64 KiB for text, so manual copying of a preview cannot be the full-content
recovery contract. The named-source crash drill does not establish unsaved
draft restart recovery. Implement an explicit full-byte, revalidated checkpoint
resume/copy route, preserving the old artifact and protecting other live work.

## R01 — Read-only Save As contradicts the source contract

Priority: **medium; required correction**. Owner:
[M3-11-R1](../tasks/M3-11-R1.md). DOC-01/02; SAVE-05; SPEC S05.2.

A disposable UTF-8 source with mode 0444 opens correctly as native view-only,
but its Save As button is disabled. The
[session coordinator](../../src/application/writingSession.ts) also refuses
all read-only Save As calls. The
[contract test](../../tests/contract/writing-session.test.ts) explicitly
expects this blanket refusal, so the passing test reinforces contract drift.
S05.2 requires viewing and Save As for read-only files.

Native [Save As publication](../../crates/screenwriter-core/src/documents/save_as_store.rs)
validates the registration/token and writes a fresh file, without requiring a
write to the original source. However, the ordinary coordinator first requires
a checkpoint of the old registration; native recovery ownership intentionally
requires exclusivity. Correct the coordination rather than weakening native
ownership, modifying source permissions, or taking another writer's lease.

## R04 — Integrated large-row typing has sustained event-loop stalls

Priority: **high; required investigation/correction**. Owner:
[M3-04-R1](../tasks/M3-04-R1.md). EDIT-01/06; QA-02; INV-14/18.

The 2,400-row, 157,290-byte forced-Action fixture opens in the default app with
capture/completion/recovery/source cadence active. A trusted Ctrl+End and DOM
caret audit establish its final text position. Allowing the input queue to
drain establishes all 120 trusted physical inputs and exact final source bytes.
The complete tmpfs sample nevertheless records key-to-rAF p95 **436 ms**, max
**592 ms**, and **119/120** samples above 100 ms; Btrfs records p95 **451 ms**,
max **612 ms**, with **116/120** above 100 ms. Raw key timestamps, proxy
samples and expected/actual source hashes remain in the artifact root; the
filesystem comparison and exact commands are in evidence.

Earlier probes ended before the queued input had drained; their partial
delivery/source snapshots do not establish lost author text or a passing
performance result. The final runner checks readiness/end navigation, waits
for complete trusted delivery, and saves only after that trace is complete.
The source/input correctness check passes; responsiveness remains unresolved.
S13 requires investigating repeated stalls above 100 ms. Profile production
capture/derived work and input dispatch before a bounded correction. The rAF
proxy does not certify compositor paint, calibrated page workloads or full S13.

## Remaining safety audit

- **Source preservation:** independent no-op oracles cover BOM, CRLF/mixed
  endings, whitespace, missing EOF newline, title/unknown/raw/hidden regions,
  dual speech and rich content. Edited-source/Undo audits retain context.
  Invalid UTF-8 remains read-only with exact original bytes. R03 is the required
  accepted-draft failure gap; no source overwrite was observed in that case.
- **Stale results and identity:** reviewed immutable capture/session/version
  checks, serial controller receipts and resolved-baseline rules, completion
  offer/caret validation, Save As retirement, native replacement receipt
  validation before editor mutation, frozen restore/close and explicit risk
  invalidation. Shared race tests and actual lifecycle drills cover the declared
  paths. R03 shows that those controller checks cannot account for a live edit
  that never reached the controller.
- **Privileges:** the default command registry excludes proof commands by
  feature configuration. Pickers run native worker code; strict envelopes carry
  opaque identities/tokens, not arbitrary paths or shell strings. Capability
  permissions are only event listening and window close. Native anchored,
  no-follow publication, exclusive destination creation, lease and metadata
  checks remain intact. WebKit automation is enabled only by the test process
  environment; no app driver plugin or runtime test route was added.
- **Content and egress:** production source has no fetch/WebSocket/beacon
  client, remote fonts, telemetry or arbitrary shell execution. Clipboard HTML
  uses inert template parsing and inserts text; Chromium interception of hostile
  HTML observed zero external requests, executable markup or script execution.
  Default WebKit resource entries are embedded only. This is a source/resource
  and intercepted-browser audit, not an OS packet capture. CSP still has local
  development-server connect allowances; offline package/network hardening
  remains the existing M6 gate.
- **Failures/durability:** workspace tests retain the native filesystem fault,
  interruption, lease/identity and publication matrix. Default-app drills prove
  ordinary permission failures, exact checkpoint SIGKILL/restart, history
  isolation and preservation of external/local generations. Actual disk-full,
  hardware power failure, other filesystems/platforms, installed/offline
  adoption and Local v1 remain outside this bounded gate.
- **Input/performance limits:** trusted native clipboard/Unicode/IME and
  completion/keyboard checks run with production saving mounted. rAF timing is
  a proxy; neither physical rows nor previous proof workloads certify printed
  pages/compositor paint/full S13. Any failed large-row run stays recorded and
  cannot supply a passing timing claim.
