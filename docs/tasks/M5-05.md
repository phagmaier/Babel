# M5-05 Authoritative read-only preview and page-count freshness

Status: **planned**
Dependencies: M5-02, M5-03
Requirements: PDF-02, UX-01, SEC-01/02, QA-01/02; INV-10/11/13/14

## Read

- SPEC S08 (continuous editor), S12.5, S13 latency
- ADR [0004](../decisions/0004-continuous-editor-pdf-preview.md), [UX](../ux.md), [editor behavior](../editor-behavior.md), the M5-02 port

## Own and deliver

A read-only preview surface (planned `src/app/PublicationPreview.tsx`) and a
page-count status. Both show the M5-02 artifact for an exact captured version.
Choose the local viewing technology in an ADR: a bundled offline PDF viewer
library, or native page rasterization by the same helper. Either way there is
no upload service, no second layout engine and no browser print CSS.

## Acceptance

- Preview and page count come from the same job, profile, fonts and snapshot.
  Typing invalidates freshness and shows "Updating" or "Preview from saved
  version". A cancelled or stale job never replaces a newer result.
- Rendering and display stay off the keystroke path. Bounded typing-latency
  regressions are measured against M4 baselines, separating rAF proxies from
  paint.
- No page markers in the editor (no source map). Page references appear in
  Script Check only with a matching layout map, which this adapter lacks.
- Keyboard focus, read-only semantics, zoom/theme and failure states are
  accessible. Helper failure shows a clear error and keeps editing and saving.

## Verification

- Planned `pnpm exec vitest run tests/ui/PublicationPreview.test.tsx
tests/contract/publication-freshness.test.ts` with stale/supersede races,
  `pnpm test:browser`, and a native release drill (type → updating → fresh
  count; stale result refused) on tmpfs and Btrfs.
- Evidence: [M5](../test-evidence/M5.md).

## Excludes

Export destination (M5-06), editable page mode and page markers (M8).
