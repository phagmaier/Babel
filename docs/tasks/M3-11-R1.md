## Owned paths and deliverable

Read-only Save As coordinator/UI and narrow native publication contracts,
focused tests and owning docs; coordinator owns task/status/trace. Meet S05.2
without gaining ownership of or writing the original source.

## Acceptance

- Permission-read-only and already-owned sources can publish an exact standalone
  copy through native Save As and adopt a fresh independent identity when safe.
- Do not checkpoint/write a registration lacking exclusive recovery ownership.
  Original bytes/ownership/recovery remain intact; fresh source is verified.
- Cancellation/publication/release/adoption failure keeps a usable original view
  and preserves any already-published copy. Existing destinations never overwrite.
- Invalid encoding/unsafe input retains exact bytes and conservative viewing;
  copying must never imply successful decoding or silently normalize the source.
- Replace the test that mandates blanket Save As refusal with tests for the
  required behavior, preserving ordinary read-only Save/edit refusal coverage.
- Shared gates, native publication/identity matrix and actual permission-read-only
  Save As/cancel/reopen on tmpfs/Btrfs. Update M3 evidence and trace.

## Boundary

No chmod of an owner's source, lease takeover or broader filesystem capability.
