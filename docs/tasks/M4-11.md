# M4-11 Bounded offline spellcheck integration proof

Status: **open — ready after M4-00**
Dependencies: M4-00; completed M3-08/13 native input gates
Requirements: UX-02, SEC-01/02, QA-01/02; INV-01/03/11/14/16/17/18

## Read

- SPEC S08.5/S14/S19
- [UX](../ux.md), [development](../development.md), [testing](../testing.md), native input evidence and exact locked runtime/platform dependencies

## Own and deliver

Isolated synthetic native spellcheck probe, platform/dictionary coverage report in M4 evidence, focused contract/probe tests and an ADR selecting a verified local integration or recording a blocked proof. Prefer the existing WebView native dictionary; evaluate one local-engine fallback only if evidence shows native behavior is insufficient.

## Acceptance

- Actually test offline suggestions/correction, language selection, ignore/add persistence, Unicode/IME, name handling and native context menus with the existing sole editor. Spellcheck is advisory; correction is explicit/Undoable and does not corrupt origin metadata/marks.
- Identify dictionary/resource availability, supported languages, engine/license/packaging obligations and app-versus-system preference scope. No global dictionary/settings mutation in the proof; use disposable task-local profiles.
- Record evidence for the provisional Linux target only; untested platforms stay open. Missing dictionaries or insufficient APIs are an explicit failed/blocked capability, never silently replaced by a cloud service or fake success.
- If a fallback is necessary, fetch current official library documentation at implementation, pin/license it and prove bounded off-typing-path work/resource packaging before selection. An inconclusive proof blocks M4-12 and the M4 exit; it does not authorize an unbounded engine search.

## Verification

- Document the exact native proof invocation and synthetic cases when created; M4-00 shared checks for executable changes. Use offline request observation and actual native suggestions/language/ignore/add/correction/Undo inspection, with dependency/resource inventory.
- Filesystem matrix applies only if a native dictionary publication adapter is introduced; pure probe/API tests do not need it. Evidence: [M4](../test-evidence/M4.md).

## Excludes

Production activation (M4-12), cloud grammar/AI, paid engines, privileged dictionary installation, global settings and other-platform certification.
