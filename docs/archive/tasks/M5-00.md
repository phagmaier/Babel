## Verification policy for M5 implementation tasks

Each brief's focused command is **planned** until its named test exists. It
supplements the [required shared checks](../../development.md#commands): `pnpm
check`, `pnpm test:browser` when frontend/DOM changes, `cargo fmt --all --
--check`, `cargo clippy --workspace --all-targets --locked -- -D warnings` and
`cargo test --workspace --locked`, with the pinned toolchains. Native behaviour
is reviewed on the default release (`pnpm tauri build --no-bundle`). Changes to
dependencies, resources or packaging also require `pnpm tauri build` and an
offline (network-namespace) run of the built package.

Renderer output is verified through layout/text/bounding-box assertions and
reviewed rendered-image goldens, never PDF checksums (INV-13). Golden
expectations generated by the implementation need independent review before
they are accepted. Native filesystem work (job output, export publication)
runs on tmpfs and Btrfs. Pure profile/assessment logic needs no second
filesystem run. Record failures, fixture hashes, measurement limits and
host/viewer versions in [M5 evidence](../../test-evidence/M5.md).

Lasting packaging, viewer, profile-implementation and dependency decisions get
an ADR when implemented, not speculatively here.
