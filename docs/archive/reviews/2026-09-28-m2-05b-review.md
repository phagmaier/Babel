## Decision: corrections required before acceptance

### R1 — Source receipt can precede source-directory durability (P1)

In [complete_replacement](../../../crates/screenwriter-core/src/documents/choices_store.rs), finalization verifies bytes and publishes/syncs `confirmed`, then returns a `sourceFile` receipt and clears uncertainty. It never syncs the source directory. The ordinary save path does sync that directory after rename, but an interruption at its `Replaced` or `BeforeDirectorySync` gate occurs first. Finalization therefore cannot rely on the original operation having completed that step.

Counterexample: stop an ordinary synthetic save at `Replaced`, then finalize. The current implementation returns a completed receipt. An interposed `fsync` logger observes only the private source-save transaction directory being synced during finalization, with no sync of the source parent. The observation reproduced on tmpfs and Btrfs. This is native syscall observation with a simulated interruption, not a power-cut test.

This violates the success boundary in [SPEC S10.4](../../../SPEC.md#s10) and INV-04/10. The existing finalize test stops at `Verified`, after the source-directory sync; it cannot catch this missing step. Correction must complete applicable source/file/directory durability and revalidate before confirming/acknowledging, with failure returning no receipt and preserving uncertainty/generations. Add meaningful pre-directory-sync and sync-failure coverage, including retry/restart and the already-confirmed branch.

### R2 — View-only relink mutates identity/lease storage (P2)

[relink_selected](../../../crates/screenwriter-core/src/documents/choices_store.rs) validates the selected target's eligibility but does not require the calling registration to own the document or verify its existing leases before `link_loose_identity` writes a registry entry. [ADR 0017](../../decisions/0017-explicit-recovery-choices.md) explicitly requires exclusive ownership for relink.

Counterexample: one service owns a loose source; a second service opens it view-only. The second service relinks that registration to another eligible loose file. The call succeeds, changes the registration's anchor/source snapshot and grows the app-data directory from four entries to seven (new identity/lease artifacts). The returned ownership remains view-only. Reproduced on tmpfs and Btrfs. No manuscript was overwritten by the reproduction; this is an authority/contract failure, not demonstrated author-content loss.

The existing relink test refuses a read-only **target**, not a view-only **caller**. Require exclusive registration/document ownership and valid held leases before any relink mutation. Do not require the obsolete source pathname to remain present: genuine rename/missing-source relinks must still work. Tests must cover second-owner/view-only refusal, invalidated leases and byte-identical stores on refusal, alongside successful loose/managed moves.

int fsync(int fd) {
    int (*real_fsync)(int) = dlsym(RTLD_NEXT, "fsync");
    char descriptor[64], target[4096];
    snprintf(descriptor, sizeof(descriptor), "/proc/self/fd/%d", fd);
    ssize_t n = readlink(descriptor, target, sizeof(target)-1);
    if (n >= 0) { target[n] = 0; fprintf(stderr, "REVIEW_FSYNC %s\n", target); }
    return real_fsync(fd);
}
